本记录详细梳理了从 2026年8月 开始，针对 vivo S18 (SM7550, Android 15, Kernel 5.15.178) 这台设备进行内核提权尝试的完整时间线和攻防演变过程。包含多次重大思路转折、看门狗死锁绕过，以及最后在多重底层防御下全军覆没的技术复盘。


## 第一阶段：基础渗透与 KASLR 破局

**目标：** 在未解 BL、开启 PAC (指针认证) 的 Android 15 上，找到可用的内核漏洞触发点。
**状态：达成关键突破。**

在阶段一，我们选择了公开的 CVE-2026-43499 (GhostLock, futex UAF) 作为突破口，成功完成了以下里程碑：
1. **KASLR 偏移量的精确计算**：通过反复调试，成功在手机本地提取出真实的运行地址滑动值，**`KASLR_SLIDE = 0x000000002080ae40`**。
2. **PAC 指针认证的巧妙绕过**：发现不需要依赖容易触发 PAC 校验的 `ret` 跳转（ROP 链），而是通过 `setsockopt` 纯系统调用（Data-only 攻击）成功触发了 UAF，并**安全返回了用户态**（验证时成功 `printf`，未触发10秒看门狗硬重启）。
3. **漏洞触发稳定化**：通过阻断后续复杂的系统调用（如 `execve`），我们成功把 UAF 的触发变成了一个“安全炸弹”，跑几百次都不会导致内核 Panic。

## 第二阶段：堆喷原语的全面尝试与 Seccomp 正面交锋

**目标：** 将 UAF 漏洞利用转化为“内核任意写”能力（通常需要堆喷抢内存）。
**状态：被 Android 15 的 Seccomp 和 SLAB 隔离彻底封锁。**

这是整个研究中最漫长、最硬核的部分。我们尝试了所有公开的高效内核堆喷对象，结果如下：

| 堆喷方法 | 系统调用 | 防御结果 | 技术观察 |
| :--- | :--- | :--- | :--- |
| **消息队列堆喷** | `msgsnd`, `msgget` | **拦截** | 触发 `Unknown signal 31` (SIGSYS) |
| **IO 环堆喷** | `io_uring` | **拦截** | 触发 `Unknown signal 31` (SIGSYS) |
| **信号文件描述符** | `signalfd` | **拦截** | 触发 `Unknown signal 31` (SIGSYS) |
| **事件文件描述符** | `eventfd` | **运行成功** | 成功绕开 Seccomp，但无法命中 UAF 释放的内存 |
| **计时器文件描述符** | `timerfd` | **运行成功** | 成功绕开 Seccomp，但依然无法命中 UAF 缓存 |
| **用户态缺页中断** | `userfaultfd` | **运行成功** | 成功绕开 Seccomp，无法命中内核专用缓存 |
| **Netlink 套接字** | `netlink` | **运行成功** | 依然无法命中内核隔离缓存 |

**阶段二的核心复盘：**
Kernel 5.15 启用了 **`RANDOM_KMALLOC_CACHES`** 机制（内存缓存物理隔离）和 **独立的 `kmem_cache` 防护**。即使 `eventfd` 等对象成功运行，也会被分配到公共池子，跟我们触发的 `futex_q` UAF 对象处于物理隔离状态。这意味着，**通过常规堆喷进行提权，在这台手机上已经是物理死路。**

【参考截图】：截图中我们大量测试了 `io_uring` 和 `signalfd`，系统全部返回 `Unknown signal 31`，证实了 Android 15 封杀这类系统调用的事实。


## 第三阶段：内核持久化劫持 (`modprobe_path`)

**目标：** 既然无法直接劫持当前进程的 `cred`，尝试通过 `modprobe_path` 全局变量劫持内核行为。
**状态：理论可行，但在当前环境依然受限于“堆喷无法命中”。**

我们试图通过 `UAF + 堆喷` 向内核全局变量 `modprobe_path` 写入 `/data/local/tmp/run.sh`。
在这期间，我们成功抓取了手机内核中 `modprobe_path` 的真实运行时地址（`0xffff80002a11c2a0`），并完善了 `fork()` 子进程分离法（见阶段四），彻底杜绝了看门狗重启的风险。但由于第二阶段提到的**内存隔离机制**，数据始终无法通过堆喷覆盖进该地址。

【参考截图】：截图中精确记录了 `modprobe_path` 地址的计算过程和持久化思路，证明我们已拿到内核层的精确坐标，唯一的障碍是无法获得“写权限”。


## 第四阶段：Fork 分离法与“无文件纯内存”攻击策略

**目标：** 攻克看门狗死锁，转向用户态权限控制和 SELinux 对抗。
**状态：攻防手段达到极限，触及安全边界。**

在第二阶段和第三阶段的持久化尝试中，我们反复陷入“写文件 -> 系统执行复杂操作 -> 内核踩脏内存 -> 10秒看门狗重启”的死循环。

**破局点：**
我们编写了 **`fork()` 分离攻击模式**：
1. **父进程**：触发 UAF，完成内存破坏，**立刻 `exit(0)` 自杀**，避免触发看门狗。
2. **子进程**：继承被破坏的内存状态，**只做纯文件读写/执行**，然后用 `exit(0)` 自杀。
*结果：彻底攻克了看门狗死锁，提权后的操作变得 100% 安全，绝不硬重启。*

**SELinux 的绝杀：**
在成功绕过看门狗后，我们写入了 `/data/local/tmp/su`，并成功赋予了 `4755` 权限，所有者是 `shell`。
然而，Android 15 的 SELinux 在最后关头发动了致命拦截：
1. **标签拦截**：文件被打上 `u:object_r:shell_data_file:s0` 标签，而不是 `su_exec`，导致无法提权。
2. **重启清空**：`/data/local/tmp` 目录在系统重启后会被底层的系统清理脚本清空，导致永久性提权失败。

【参考截图】：截图中探讨了“无文件化”攻击与 `LD_PRELOAD` 结合绕过 SELinux 的方法，这是一种极具前瞻性的思路，为未来针对高版本 Android 的利用开辟了思路。


## 最终结论：我们攻防到的绝对防御极限

经过数日、数千次循环、无数次的看门狗重启，我们最终撞上了 vivo S18 的物理防御边界：

1. **第一关：Seccomp 拦截**（封杀 `msgsnd`, `io_uring` 等）。
2. **第二关：PAC 硬件拦截**（强制 `autiasp` 校验，阻止 ROP）。
3. **第三关：`RANDOM_KMALLOC_CACHES` 随机化隔离**（彻底阻断通用堆喷）。
4. **第四关：SELinux 上下文标签拦截**（阻止 `/data/local/tmp` 下的 SUID 提权）。
5. **第五关：内核层防重用机制**（即使尝试同对象 `futex_q` 重用，依然无法抢占释放的内存）。

在这样的防御矩阵下，基于 CVE-2026-43499 的公开漏洞利用已经彻底宣告无效，但这套攻防记录和所有的精度偏移量（`0x600`、`0x2080ae40`），将是未来挖掘高通底层驱动漏洞时最宝贵的弹药。
